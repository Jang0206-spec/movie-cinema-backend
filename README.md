📌 Movie Cinema (온라인 영화 예매 및 리뷰 시스템) - V1.0.0
상태: Phase 1 (JSP/Servlet 레거시 코드 백업 완료 / Spring Boot 리팩토링 준비 중)
본 프로젝트는 학부 과정에서 개발한 JSP/Servlet 기반 원본 서비스입니다. 현재 이 저장소는 과거의 레거시 코드를 백업한 상태이며, 향후 현대적인 백엔드 아키텍처(Spring Boot + 분산 인프라)로 리팩토링하며 기술적 부채를 해결해 나가는 과정을 기록할 예정입니다.

⚙️ 오리지널 아키텍처 및 개발 환경 (V1.0.0)
Language & Framework: Java (JDK 17), JSP/Servlet (MVC 패턴 표준 준수)

Database: MySQL 8.0

Web Server: Apache Tomcat 11.0

IDE: Eclipse

💾 데이터베이스 설계 (ERD 요약)
총 4개의 핵심 엔티티를 구성하여 각 데이터 간의 트랜잭션을 구현했습니다.

member (회원): 사용자 ID, 암호화된 비밀번호, 연락처, 권한(role을 통한 관리자/일반 사용자 구분).

movie (영화): 영화 제목, 감독, 가격, 러닝타임, 포스터 이미지 경로.

movie_reservation (예매): 회원이 예매한 영화, 상영 날짜/시간, 인원 수, 좌석 정보(문자열 형태), 총 결제 금액.

review (리뷰): 회원이 영화에 남긴 평점, 한줄평 내용.

🚀 주요 구현 기능
1. 세션 기반 인증 및 권한 제어
보안: 사용자 비밀번호는 평문 저장을 방지하기 위해 SHA-256 해싱 알고리즘을 적용하여 단방향 암호화 수행.

권한 분리: HttpSession 객체를 활용하여 로그인 상태를 유지하고, 관리자(admin)와 일반 사용자의 접근 가능한 페이지 및 기능(예: 리뷰 삭제 권한)을 엄격히 분리.

2. 영화 예매 및 좌석 데이터 처리
별도의 좌석 테이블을 두지 않고, 여러 좌석(예: A1, B2)을 "A1,B2" 형태의 단일 문자열로 결합하여 DB에 저장.

조회 시 Java의 split() 함수를 통해 문자열을 파싱하여 화면에 '예매 완료된 좌석'으로 렌더링 처리.

3. 대용량 데이터 조회를 위한 페이징
한 화면에 너무 많은 데이터가 로드되는 것을 방지하기 위해 MySQL의 LIMIT ?, ? 구문을 활용하여 한 페이지당 4개의 영화만 가져오도록 쿼리 최적화.

🛠️ 기술적 챌린지 및 트러블슈팅 (V1 기준)
1. 동적 경로 제어로 404 에러 방어

이슈: 폴더 깊이가 다른 여러 JSP 파일에서 하나의 공통 header.jsp를 공유할 때, 상대 경로(../) 사용 시 링크가 깨지는 현상 발생.

해결: JSP 내장 객체인 request.getContextPath()를 사용하여 프로젝트 최상위 루트를 동적으로 가져와 모든 환경에서 견고하게 작동하도록 수정.

2. 데이터 공백으로 인한 권한 처리 오류

이슈: DB 상에서 관리자 권한(admin)을 부여했으나, 시스템 로직에서 계속 일반 유저로 인식되는 논리 오류 발생.

해결: System.out.println 콘솔 디버깅을 통해 DB 데이터 뒤에 눈에 보이지 않는 공백이 포함되어 equals() 비교가 실패함을 원인으로 규명. 데이터를 가져올 때 .trim() 메서드를 적용하여 데이터 무결성 확보.

🗺️ Refactoring Roadmap (향후 고도화 계획)
[x] Phase 1. 레거시 코드 백업 및 분석 (완료)

Eclipse 환경의 JSP/Servlet, 원시 JDBC 기반 코드 Git 업로드.

[ ] Phase 2. 인프라 현대화 및 구조 전환 (진행 중)

IntelliJ + Java 17 + Spring Boot 3.x 환경으로 마이그레이션.

Spring Data JPA 도입을 통한 데이터 접근 계층(Repository) 객체지향적 고도화.

[ ] Phase 3. 동시성 제어 및 데이터 설계 최적화

기존 콤마 분리 방식("A1,B2")의 좌석 저장 구조가 대용량 트래픽 환경에서 가지는 무결성 한계를 인지. 이를 NoSQL(Redis) 기반의 분산 락(Distributed Lock) 제어로 리팩토링하여 선착순 예매 환경에서의 데이터 정합성 확보.

[ ] Phase 4. 분산 스트리밍 아키텍처 확장

Apache Kafka 메시지 큐 도입을 통한 이벤트 기반 비동기 예매 시스템 및 알림 파이프라인 구축.
